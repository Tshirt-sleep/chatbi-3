# ChatBI 产品介绍网站：内容目录与表达边界

> 目的：作为 ChatBI 产品介绍页的长期内容提纲；介绍页与问数应用部署在同一 Netlify 站点下。面向业务用户、产品同行和作品集读者；以产品经理视角讲用户问题、产品体验、指标口径、验证与取舍，不以工程架构为主线。当前平台没有接入大模型，介绍页不得把模型能力写成现状。

## 介绍目录

介绍页面向业务使用者和产品同行，以产品经理视角讲清当前可用能力、证据与边界。章节顺序与网站目录保持一致：

1. **问题与目标**：描述经营查数中的常见困难，并标明这是产品假设，不是用户研究结论。
2. **面向谁用 · 怎么问**：把角色与任务合并；呈现管理者、运营/产品经理、数据分析师的实际示例问法和结果重点，说明角色不代表真实权限。
3. **产品能做什么**：列出当前支持指标、分析维度、结果形态、澄清与边界反馈。
4. **一次问数流程**：选择视角/输入问题 → 固定规则识别 → 服务端校验 → 必要时澄清或执行受控查询 → 展示结果与依据。公开版不调用大模型。
5. **会话与历史管理**：说明新建、切换、删除会话和删除单条提问的区别，并交代浏览器与后端的保存边界。
6. **数据与指标口径**：说明合成 Mock 数据、指标定义、时间窗口及时区，以及暂不支持的指标。
7. **答案如何值得信任**：介绍可查看的指标口径、时间、筛选条件、数据集来源，以及澄清/拒答行为。
8. **如何验证效果**：展示固定问题、边界场景、查询结果、页面交互的验收方式和现有证据，避免宣称覆盖所有用户问法。
9. **产品实现方式**：从 AI 产品经理的产品判断与 Vibe Coding 实践出发，说明假设、范围、原型和证据迭代。
10. **SDD 规范驱动开发**：说明 PRD、SDD、语义目录和黄金问题如何把产品意图、口径、系统行为与验收串起来。
11. **当前版本与下一步**：区分公开版已实现能力与待验证方向；尚无上线承诺的内容不写成已排期功能。
## 已纳入介绍页的当前使用说明

- 三种分析视角的示例问题与前端 `QUERY_PERSPECTIVES` 保持一致：管理者关注规模与趋势；运营/产品经理关注商品、类目、渠道；分析师关注指标口径、周期和分组。
- 回答结果描述为指标卡、图表/表格、统计周期及依据等结果形态；实际数值必须来自演示站本次查询，不把静态示意图数字说成生产数据。
- 会话列表与消息在当前浏览器本地保存；整段会话删除会移除本地历史；单条问答移除只影响本地页面展示，后端运行态历史不会因此删除。后端会话在进程内存中，重启可能清空。
- 数据口径说明以当前电商语义目录为准：销售额为有效订单折后实付金额之和、按支付时间统计且不扣退款；有效订单数去重；退款订单率不是退款金额率。
- 产品优势以可验证的体验表达：自然语言入口、按业务视角组织示例、结果附口径依据、歧义澄清和范围内查询。避免写成对真实用户效率或经营收益已有验证的结论。

## 对外表达必须遵守

- 当前公开演示使用合成 Mock 数据；不得描述为客户真实经营数据或真实用户验证。
- 当前公开演示没有接入大模型；介绍页不设置“大模型职责/模型能力”章节，不把未来计划描述为现状。
- 当前产品按固定规则识别支持范围内的问题，随后由后端受控查询产生答案数字。不要宣称模型正在做意图理解。
- 退款订单率不是退款金额率。未支持指标和复杂归因要明确标注为范围外。
- 角色切换是演示身份，不是真实认证或权限系统；网页本地会话记录与服务器会话运行态有不同的持久化边界。
- “基于数据给建议”尚未实现。若未来开发，需另行评估汇总数据外发、证据引用、无依据推断、告知和费用边界。
- 介绍页中的“体验演示”必须链接到 `https://for-chatbi.netlify.app/`；演示网站应能返回介绍页。两者分别部署前须分别审核和授权。

## 部署与双向连接

当前问数站 Netlify 构建根目录配置位于仓库根 `netlify.toml`，使用 `frontend` 为 base、`npm run build` 为构建命令、`dist` 为发布目录。介绍页是 `product-intro/` 下的静态 HTML/CSS/JS，由前端构建脚本复制到同一个发布目录的 `/product-intro/` 子路径，不单独创建 Netlify Site。

介绍页与 ChatBI 使用同一个 Netlify Site 和生产部署，问数页入口指向 `/product-intro/`，介绍页内的演示按钮指回站点根路径。Netlify 无需增加第二个项目或额外环境变量。

## 建站实现顺序

1. 用本提纲搭建介绍页信息架构和响应式视觉稿。
2. 先在本地预览，检查桌面/手机布局、文案真实性、可访问性和演示站链接。
3. 将介绍页纳入现有 ChatBI Netlify 构建，通过 `/product-intro/` 提供访问；在 ChatBI 顶栏设置介绍页入口。
4. 上线后核对 `/product-intro/`、ChatBI 顶栏入口和介绍页返回演示的链接。
