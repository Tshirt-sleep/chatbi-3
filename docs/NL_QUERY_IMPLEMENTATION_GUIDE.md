> 用途：把已审核通过的业务问法清单转成可逐步执行、逐步验收的实施任务。
>
> 当前原则：只支持语义目录中已批准的电商问数能力；规则优先，规则未识别时才可由模型补充结构化意图；后端校验意图并映射到固定查询模板；答案数值必须来自数据库查询。模型不生成 SQL、不访问数据库、不提供结果数值。

> 现状提醒：自然语言问数候选已推送到临时分支，尚未合并或部署；线上与候选版本不一致。每阶段开始前都要查看 `git status` 和相关差异，不能覆盖、清理或假设候选已经部署。公开演示当前关闭模型调用。本手册本身不授权部署、启用公网模型或修改云端设置。

## 怎么使用本手册

1. 按阶段顺序推进，一次只执行一个阶段。
2. 将该阶段的“可复制提示词”交给 AI coding 工具；每个阶段结束后先检查结果和差异，再决定是否继续。
3. 需要改代码的阶段，提示词要求先列出修改方案。未经你批准，不扩大到其他指标、维度或过滤条件。
4. 除非某阶段明确写出，否则不要运行会重置数据、写入云数据库、真实调用模型、提交或部署的操作。
5. 所有验收使用合成 Mock 数据。本地 API Key 只保存在本机被 Git 忽略的配置中；不要粘贴、打印或写入对话、日志、测试报告或前端。

## 已审核的能力边界

- 已支持能力及问法以本项目业务验收清单和活动语义目录为准：销售额、有效订单数、客单价、特定场景的商品退款订单率，以及日期、商品、品类、渠道等已启用维度。
- “最近一个月”按 Mock 快照最新日期向前滚动 30 天，使用半开区间；当前示例为 `[2026-07-02, 2026-08-01)`，时区 `Asia/Shanghai`。
- “最近一个月各销售渠道表现如何/卖得怎么样”按渠道展示销售额和有效订单数；“买得怎么样”需要澄清，不能擅自套用上述指标。

- 本阶段不支持任意数据库问题，不默认支持用户自定义品牌、地区、状态等目录外过滤条件。

## 阶段 6：真实模型意图与本地 Mock 查询联合验证（需另行批准）

### 目标

在离线测试全部通过后，评估真实模型能否将已批准的规则未覆盖问法解析为正确意图。它不是当前计划自动授权的操作。

### 具体任务与文件范围

- 仅使用已审核的合成测试问法和本地 Mock 数据；每次运行最多一个模型请求。
- 真实调用前，先审核实际发送的输入范围、调用次数和输出保存路径。
- 不读出或要求你提供 API Key；只在本地安全检查变量是否存在/为空。
- 模型只接收解析问题所需的白名单片段和最小语义定义，不接收数据库结果、订单明细、真实业务数据或用户身份。
- Harness 分两步验收：先核对模型结构化意图、后端校验和模板映射；意图匹配且为 `ready` 后，再单独用固定模板执行本地 Mock 查询。模型不接收查询结果，也不生成答案数值。
- 查询执行前，Harness 必须确认连接目标是仓库内 `data/local/chatbi.sqlite`，且数据库 Mock manifest 与仓库生成的 manifest 版本和时区一致。不能证明本地 Mock 身份时必须停止查询。
- 脱敏报告可以包含 `intent_passed`、`backend_validation_status`、`template_id`、`query_execution_status`、`query_executed`、`query_template_id`、`query_result_row_count`、`query_dataset_id`、`query_dataset_version`、`query_mock_data`；不得包含查询结果值。
- 预计读取 `harness/llm_golden_cases.json`、`harness/run_llm_eval.py`；仅在另行批准时运行。
