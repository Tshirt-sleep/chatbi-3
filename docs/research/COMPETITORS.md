# P1 竞品调研与比较

- 调研日期：2026-11-06
- 项目方确认的调研偏好：只看 ChatBI 专项产品；首期优先做可演示的电商 ChatBI。
- 项目方确认：选取两到三个竞品作为重点分析对象；其余产品只保留为辅助参考，不扩大主比较范围。
- 范围：优先检查官方产品页、官方文档和官方帮助中心；此文记录厂商公开描述，不代表独立性能测试或用户口碑验证。
- 证据分级：**公开事实**为官方来源明确描述；**分析推断**为基于公开资料对产品方向的归纳；**待验证**表示需通过产品试用、版本/套餐核实或项目方确认。

## 1. 重点竞品比较

按项目方确认，重点比较聚焦三个与项目目标最贴近、资料相对可用的对象：腾讯云 ChatBI、阿里云 Quick BI 小Q问数、开源 DataEase SQLBot。SmartBI AIChat 和个推 ChatBI 保留为国内市场辅助参考；DB-GPT 与国际产品属于邻近/背景参考，不纳入主要横向结论。

| 产品 | 面向与问数方式 | 语义/业务上下文 | 答案呈现与可追溯 | 权限/部署/限制（公开资料范围） | 对本项目的启发 |
|---|---|---|---|---|---|
| 腾讯云 BI ChatBI | ChatBI 专项助手；支持多轮问答、模糊问题追问、图表与分析结论 | 官方资料提到智能选表、多表关联；具体业务语义配置细节需进一步看配置文档/实测 | 可返回图表结论背后的 SQL，便于校验，也支持导出分享 | 支持混元、DeepSeek；可在 PC/H5/嵌入端使用。具体套餐/部署约束需核实 | SQL/查询依据可见、歧义主动澄清是重要体验；比较“受控查询计划”与直接展示 SQL 的易用性 |
| 阿里云 Quick BI 小Q问数 | ChatBI 问答入口，支持自然语言、快捷问题、多轮对话、历史对话及数据集选择 | 使用前需准备数据集并进行问数配置；用户只可对有权限数据集问数，可预览字段和数据 | 可在对话中查看字段信息、数据预览、分析结果；能力包含不同智能分析 Agent | 官方文档标明属于增值模块；所支持站点因功能/时间而异 | 数据集选择、字段预览和问数权限可帮助用户明确当前问数上下文 |
| DataEase SQLBot（开源） | 开源 ChatBI/Text-to-SQL 产品，基于大模型与 RAG 对话式问数 | 支持自定义提示词、术语库和 SQL 示例校准 | 提供 Web/弹窗嵌入和 MCP 调用；功能实测仍需另行验证 | GitHub README 声明 GPLv3 衍生义务及保留 Logo/版权等约束；部署文档包含 Docker 方式 | 对术语库、SQL 示例、反馈闭环有直接参考价值；若采用代码需先评估许可证约束 |

## 4. 共同模式（分析推断）

1. 成熟产品都把自然语言问数建立在某种业务语义或模型上下文上，而非让模型仅凭原始字段名猜口径。
2. “展示依据/可视化/来源/查询逻辑”被用来建立用户信任和支持核对。
3. 模型和确定性计算职责有所分离：自然语言负责理解/解释，受治理的指标或查询引擎负责数据计算。
4. 产品体验常覆盖澄清、追问或建议问题；自由提问不等于所有问题都应直接给答案。
5. 企业级产品将用户身份、模型可用性、权限和部署许可作为能力边界的一部分。

以上是基于官方公开页面的归纳，不能据此判断各产品的真实准确率、易用性、总体成本或客户满意度。

## 5. 初步产品机会假设（项目方已认可的设计重点）

- 以**能现场演示且答案可核对的电商 ChatBI**为首期目标。项目方已接受此定位；首期需求细节由后续 PRD 阶段确定。
- 项目方认可“答案可核对、口径清楚、问数过程可检查”作为产品设计重点。
- 电商销售额、订单数、商品/类目排行、渠道表现、时间趋势和退款率等问题均先保留在候选池；由 PRD 阶段决定哪些进入 MVP、哪些进入后续迭代。
- 大模型解析到查询计划后，在执行前由服务端校验；让用户能检查“平台理解了什么”，遇到不确定问题主动澄清。
- 语义目录和标准问题 Harness 是问数准确性的支撑底座，但要先聚焦小范围电商指标，而非首期做复杂的字典管理平台。
- 只凭市场资料不能证明产品差异化。初步差异假设可放在“面向非技术开发者、文档驱动的渐进式交付和可回归验收”，需由项目方确认目标价值。
- 通用平台能力通过领域配置与存储适配设计保留；是否在首期演示第二行业由 PRD 决定，不为“通用”提前扩大 MVP。

## 6. 调研局限与待验证项

- 当前主要使用官网、官方帮助文档和 GitHub 项目页，没有完整体验所有产品，因此无法评估实际答案准确率、操作流畅度、部署工作量和总体成本。
- 商业产品宣传描述与可获得版本可能有差异；需要以对应版本/套餐试用验证。
- 对项目而言的关键差异尚未通过用户研究验证；不能把“语义层 + LLM”本身当作差异化，因为竞品已有类似能力。
- 所有当前用户痛点、问题频度、目标角色优先级都仍是市场研究假设，不进行用户访谈；项目方确认的是本项目演示目标和范围。

## 7. P1 结论与阶段交接

1. P1 重点竞品样本为腾讯云 ChatBI、阿里云 Quick BI 小Q问数、DataEase SQLBot；SmartBI AIChat/个推为辅助参考，DB-GPT/国际产品为背景参考。
2. 项目方接受首期定位为可演示的电商 Mock ChatBI。
3. 所列电商问数问题先全部保留候选，哪些进入 MVP、哪些后续做由 PRD 阶段决定。
4. 项目方认可答案可核对、口径清楚、问数过程可检查为产品设计重点。
5. 本项目不安排真实用户访谈；用户痛点/频度保持为市场分析推断。
6. P1 到此完成。后续阶段应在项目方明确要求后启动，不因 P1 结论确认自动进入 P2。
