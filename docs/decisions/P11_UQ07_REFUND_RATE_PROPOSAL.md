# P11-UQ07 商品退款订单率决策与实现

- 状态：项目方已接受并授权；本地实现及验收进行中，尚未发布线上。
- 目标：以最小范围补齐 PRD UQ-07“最近 30 天退款率最高的商品有哪些？”。
- 当前实现：`refunds` 事件由固定种子生成，语义目录升级为 1.0.0；确定性查询只统计已完成退款，并按商品和订单去重。生产数据库更新需后续单独制定安全的增量发布与回滚步骤。

## 已确认的唯一首期口径

将用户说的“商品退款率”明确显示为 **退款订单率**，采用订单数量口径，不称为退款金额占比：

> 商品退款订单率 = 在所选支付日期 cohort 中，该商品至少有一条已完成退款的有效订单数 ÷ 该商品涉及的有效订单数。

- 有效订单：`paid` 或 `completed` 且有 `paid_at`。
- 日期范围过滤分母订单的 `paid_at`（Asia/Shanghai 半开区间）。退款事件不另按退款发生日筛选；数据集是参考日快照，指标表示该 cohort 截至快照已记录的退款订单比例。
- 商品归属：按退款对应的 `order_item_id` 找商品。某订单同一商品多条明细或多次已完成退款，对该商品的分子最多计 1 单；同一订单购买并退款多个商品时，可分别进入多个商品的分子/分母。
- 只有 `refund_status='completed'` 的事件进入退款订单分子；`requested`、`rejected`、`cancelled` 均不计为已退款。
- 部分退款和全额退款在此指标都将对应订单计 1；金额不影响比例。若以后需要金额口径，应新增独立命名的“退款金额占支付金额”指标，不能混用本指标。
- 分母为 0 的商品不展示；结果按精确比例降序，比例相同按商品 ID 升序；结果显示分子/分母订单数和百分比，明确注明“按支付日期归属，退款截至 Mock 快照”。
- “最近 30 天”沿用项目固定参考日 2026-08-01，解释为 2026-07-02 至 2026-08-01（结束日不含），与现有时间解析规则一致。

## 口径理由

1. 原问题要比较“退款率最高的商品”，订单率比退款金额率更容易解释商品退货/退款发生频度。
2. 按支付 cohort 统一分子、分母日期，避免把当期退款事件和当期支付金额混作一个比率。
3. 以已完成退款计数并对订单去重，避免申请中退款、拒绝退款、多次部分退款重复放大分子。
4. 明确结果是快照 cohort 指标，避免将其误解为按退款发生日统计的实时事件率。

## 最小实现范围与验收

1. 在生成器补充固定种子退款：覆盖无退款、已完成部分退款、已完成全额退款、同商品同订单多次退款、申请中/拒绝/取消、跨自然月完成退款；累计退款金额不超过明细实付金额。
2. 更新语义目录与退款数据规范，保持原销售额仍按支付实付且不扣退款。
3. 新增确定性查询模板与只读 SQL allowlist，不启用 DeepSeek，不让模型决定分子/分母。
4. 为退款率 UQ-07 建独立黄金结果，验证事件状态、去重、多商品订单、跨月支付/退款、并列排序、零分母和比例精度。
5. 云端现有数据库有非空业务行，不能直接运行只接受空库的 Seeder。先在隔离恢复库重建并验收；再设计安全的版本化数据更新/切换步骤，确认回滚后方可更新线上 Mock 数据。
6. 复用 `refunds` 现有表，无需新增数据库列；只有语义目录与 Mock 数据版本需按项目版本策略升级。
