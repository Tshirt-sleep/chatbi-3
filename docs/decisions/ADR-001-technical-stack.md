# ADR-001：首版技术栈与存储边界（评审稿）

- 状态：已接受（2026-11-07）
- 日期：2026-11-07
- 决策者：项目负责人

## 背景

项目目前为文档和固定 Mock 数据阶段，没有应用代码或已确定的技术栈。首版要在本地用确定性逻辑完成可核对问数，后续再接 LLM，并最终把 Mock 数据存入云数据库。项目负责人技术经验有限，优先考虑组件少、文档和示例成熟、可逐步验证、易于本地运行的实现方式。

## 决策

- 前端：React + TypeScript + Vite。
- 后端 API/领域服务：Python + FastAPI + Pydantic。
- 数据访问：SQLAlchemy；本地 SQLite；云端以 PostgreSQL 兼容数据库为目标类别。
- 生成与验收 Harness：沿用 Python；调用同一后端接口或应用服务，不另建第二套查询规则。
- 金额：数据库和领域计算使用整数分（minor units）；CSV/HTTP 使用定点十进制字符串。
- 模型：P7 才选择供应商；通过后端 Provider 接口注入，首版无模型依赖。
- 云平台：本 ADR 不选具体厂商、区域或付费服务；P9 评估后再决定。

项目方于 2026-11-07 确认上述技术栈、整数分存储、PostgreSQL 兼容云目标类别，以及公网部署前设置认证/访问控制、本地仅监听本机的约束。

## 取舍

该组合使生成器、Harness 和后端共用 Python 生态，SQLite 本地易启动，PostgreSQL 兼容目标便于云迁移。代价是前后端分离、需要维护两套依赖；若项目方希望单语言或已有熟悉技术，也可在 P4 评审时调整，之后由 P5 锁定版本。

## 影响

P5 按此建立工程骨架、依赖锁文件、SQLite schema/Seeder 和 OpenAPI 客户端边界。公网部署前仍需明确认证、网络与密钥管理策略；具体云服务仍由 P9 比较决定。
