# 电商 ChatBI 黄金问题集（结构稿）

- 状态：P2 PRD v0.3 已批准；P3 数据、语义口径及固定数据黄金预期已完成并通过阶段门核验。UQ-01 至 UQ-10 均纳入计划，UQ-07 后续迭代，其余首版。
- 精确数值：见同目录 `GOLDEN_RESULTS.md`，对应 `ecommerce_mock_v1` v1.0.0；生成方法见 `scripts/generate_mock_data.py`。
- 规则：首版遇到 UQ-07 退款率问题，应说明暂不支持。澄清型问题必须先展示澄清且不执行查询；收到用户补充后再按新条件执行并展示本轮解析与查询条件。

### 时间范围澄清用例

UQ-04、UQ-05、UQ-06 初始问题都没有时间范围，系统必须先问用户希望查看哪个时间段，不能静默查询整个数据窗口。为生成稳定的数值黄金预期，每题都使用标准澄清回复“最近 30 天”；其窗口按固定参考日解析为 `[2026-07-02 00:00, 2026-08-01 00:00)`（Asia/Shanghai）。先验证澄清轮没有执行查询，再验证补充时间后的结果。

UQ-09 的标准澄清回复为“比较 2025-08-28 至 2025-09-03 和之前一周”：当前期为 `[2025-08-28 00:00, 2025-09-04 00:00)`，对比期为 `[2025-08-21 00:00, 2025-08-28 00:00)`。该固定例子在 Mock 数据中覆盖“订单数增加、销售额没有同步增加”的情况。系统应先澄清，收到周期后再分别计算有效订单数、销售额和客单价，并应用语义目录中的恒等分解；不把数据分解描述为因果结论。

|---|---|---|---|

| NEG-02 | 无法判断指标或时间的模糊问题 | 提问澄清，澄清前不执行 | Must |
| NEG-03 | 与数据分析无关的闲聊/通用知识问题 | 提示当前助手范围 | Must |

## P3 查询计划核对摘要

所有可查询题共用有效订单过滤：`order_status IN ('paid','completed') AND paid_at IS NOT NULL`；期间按上海时区半开区间 `[start, end)` 过滤 `paid_at`。销售额为支付实付、退款前金额。UQ-04–06 初始轮只澄清，不执行查询。

| ID | 指标 | 分组 / 条件 | 固定验证点 |
|---|---|---|---|
| UQ-01 | `sales_amount`, `order_count` | 2026-07-31；订单 ID 去重 | 单值和订单数与 `GOLDEN_RESULTS.md` 一致 |
| UQ-02 | `sales_amount` | 按支付日期日分组；2026-07-25 至 2026-07-31；日期升序 | 输出 7 天，折线；本主数据每一天有有效订单 |
| UQ-03 | `sales_amount` | 2026-07-01 至 08-01 对比 2026-06-01 至 07-01 | 两期金额、差额及相对上期变化率一致 |
| UQ-04 | `sales_amount` | 澄清后最近 30 天；按商品分组；金额降序 Top 10，同额按商品 ID 升序 | 澄清轮未查询；回答后 Top 10 与固定结果一致 |
| UQ-05 | `order_count`, `sales_amount` | 澄清后最近 30 天；按唯一主要叶子类目分组 | 类目订单按涉及关系去重；27 个叶子均展示，类目间可重复计单 |
| UQ-06 | `average_order_value` | 澄清后最近 30 天；按唯一渠道分组；各组销售额除以组内去重订单数 | 渠道金额每订单只计一次，客单价与固定结果一致 |
| UQ-07 | `refund_rate` | 不执行 | 首版回复暂不支持；退款率属后续迭代 |
| UQ-08 | `sales_amount` | 按叶子类目分组；2026-07-27 至 08-01 对比 2026-07-20 至 07-25；变化额升序 | 返回两期金额和差额；结果含下降与上升类目 |
| UQ-09 | `order_count`, `sales_amount`, `average_order_value` | 先澄清两个完整 7 日周期；再分别聚合，按目录公式分解 | 标准周期及分解结果见 `GOLDEN_RESULTS.md`；不推断因果 |
| UQ-10 | 无查询 | `收入`无默认指标映射；说明销售额口径并澄清 | 澄清前不执行查询 |

UQ-04–06 和 UQ-09 的澄清交互要求：第一轮显示缺失条件/解析意图并且不执行；用户补充后按新周期重新校验并执行原问题。其他查询每轮均展示解析结果和条件。响应时间目标待 P5/P7 实际环境建立基线后确定。
