# P8-3 语义目录配置化：需求与验收草案

- 状态：需求与验收已由项目方确认；P8-3 SDD/任务规划阶段
- 版本：草案 v0.1
- 日期：2026-11-07
- 关联阶段：P8 产品化能力迭代
- 关联资料：[PRD](PRD.md)、[SDD](SDD.md)、[电商语义目录](semantic/SEMANTIC_CATALOG.md)、[P7 实现规格](P7_LLM_QUERY_SPEC.md)

## 1. 背景与问题

当前电商语义目录已在文档中定义指标、维度、术语、时间规则、策略和数据结构，但运行时的目录 ID/版本、指标定义、别名、问题意图映射和模型上下文仍分散在 Python 常量与解析逻辑中。修改业务术语可能需要同时改多处代码，造成页面解释、确定性解析和模型理解不一致。

本需求把可配置的业务语义集中为一个受校验、可版本控制、可回滚的目录，同时保留后端对白名单查询模板的控制。配置用于描述和选择已实现的语义能力；它本身不能编写或开放新的 SQL、公式或查询能力。

## 2. 目标与成功结果

1. 指标、维度、术语别名和适用规则有一个运行时唯一的、带 ID/版本的机器可读来源。
2. 确定性解析、DeepSeek 意图上下文、结果口径展示和 API 版本证据读取同一份已验证目录。
3. 目录错误、歧义和不兼容变更在查询执行前被发现，不静默猜测或降级到另一份定义。
4. 目录变更可通过版本控制差异进行评审、回归、发布和回滚。
5. 仅通过配置不能启用未经后端实现和审核的新查询能力。

## 3. 范围

### 本迭代包括

- 把当前 `ecommerce_mock_semantics` 电商目录迁移为机器可读的版本化配置；初始目录内容仍对应已确认口径和 `ecommerce_mock_v1`。
- 配置目录元数据、数据集兼容关系、指标/维度定义、别名/术语、适用范围、歧义策略和时间规则引用。
- 建立目录结构与业务引用校验，以及可在发布前运行的目录检查和黄金回归流程。
- 让 P6 确定性解析、P7 模型上下文和返回给用户的口径/版本证据使用相同目录版本。
- 通过 Git 变更差异进行维护、评审、发布和回退。

### 本迭代不包括

- 网页版语义目录编辑器、运行时热修改、普通用户自行配置指标或别名。
- 通过目录内容定义或执行任意 SQL、Python 表达式或动态公式。
- 仅靠新增一条配置就创建新的可查询指标、维度、图表或查询模板。
- 新行业/新数据集接入、多租户目录选择、RBAC 管理界面或云数据库迁移。
- 修改已确认的指标口径、数据窗口、Mock 数据或黄金答案；这类变更需单独评审。

## 4. 术语

| 术语 | 定义 |
|---|---|
| 语义目录 | 带稳定目录 ID 和版本的指标、维度、术语及规则集合 |
| 可执行能力 | 后端已经实现并显式列入允许清单的解析形状和查询模板 |
| 目录快照 | 应用启动时加载并通过校验的一版不可变目录 |
| 目录变更 | 对定义、别名、状态、兼容关系或规则引用的修改；必须改变目录版本 |

## 5. 确认的项目约束

- 项目全程使用 Mock 数据；本阶段目录只支持当前电商 Mock 数据。
- 目录定义业务语义；查询结果始终由服务端受控查询产生。
- 模型只在规则无法解析或需要消歧时参与，并只接收最小相关语义上下文。
- 目录版本和数据集版本需要出现在查询结果的证据中。
- P4 明确首版不做词典管理后台；本需求不引入 Web 编辑器。

## 6. 已确认决策与设计约束

1. 第一版以仓库内的机器可读配置文件为来源，由 Git 差异、代码评审和本地/自动检查构成维护流程；不提供网页编辑器。
2. 配置只调整已支持的语义定义、别名、状态和适用范围；新增指标或查询能力仍需后端实现和单独验收。
3. 语义口径变更升主版本、兼容扩展升次版本、纯文案修订升补丁版本。
4. 应用启动时加载并验证一份目录快照；修改需经过校验和回归后重启/重新部署，不做热更新。
5. 当前只发布一个电商目录；结构保留目录 ID，但本迭代不提供运行时多目录切换。
6. 目录文件中不放 API Key、订单行、客户信息或查询结果。
7. 配置格式采用 JSON，利用现有 Python 标准库解析，不新增格式解析依赖。

## 7. 功能需求

| ID | 需求 |
|---|---|
| SC-FR-01 | 目录必须声明唯一 `catalog_id`、语义版本、状态及兼容的数据集 ID；时区和相对日期解释策略属于语义配置；数据集实际起止日和参考日继续以该数据集 manifest 为准，避免重复维护。 |
| SC-FR-02 | 目录必须描述现有指标、维度和字段引用的稳定 ID、规范名称、业务定义、粒度/可用范围、已批准别名，以及已审核关系和聚合/去重约束；首版金额、订单、客单价等定义必须与已批准语义目录一致。 |
| SC-FR-03 | 术语可以指向一个已登记指标/维度、明确标为歧义，或标为暂不支持；歧义词不能静默映射到任一可执行指标。 |
| SC-FR-04 | 目录可声明一个语义能力对应的后端实现 ID；实现 ID 必须存在于服务端允许清单。配置不允许携带 SQL、任意字段表达式、脚本或动态公式。 |
| SC-FR-05 | 目录校验必须检查必填项、稳定 ID 唯一性、引用存在性、数据集兼容、别名冲突、状态有效性和实现 ID 白名单。校验失败须给出可定位的字段/条目错误。 |
| SC-FR-06 | 同一个已启用别名不得解析到多个不同指标或维度。确属歧义的术语必须显式标记为需澄清，且解析结果不得生成可执行计划。 |
| SC-FR-07 | 确定性解析、LLM 上下文构造、普通结果口径说明和查询证据必须从同一目录快照读取，返回的 `catalog_id` 与 `catalog_version` 必须与实际快照一致。 |
| SC-FR-08 | 目录状态非 active、数据集不匹配、目录校验失败或语义版本不兼容时，系统必须阻止查询或要求用户重开/重述；不得静默套用旧定义。 |
| SC-FR-09 | 新增或修改目录定义不会自动增加后端执行能力。若没有对应的已审核实现 ID 和允许的查询计划映射，问题必须拒答/澄清，且不得访问查询执行层。 |
| SC-FR-10 | 目录变更必须提升版本并保留可审阅的变更记录。修正文案但不改变语义可提升补丁版本；向后兼容的别名/定义扩展可提升次版本；删除/重定义 ID、改变口径或兼容性须提升主版本。 |
| SC-FR-11 | 发布目录前必须能执行目录静态校验和适用的 P6/P7 黄金回归；关键黄金结果、拒答和澄清行为发生非预期变化时，变更不得标为通过。 |
| SC-FR-12 | 回滚必须能恢复上一已发布目录版本，并恢复对应目录版本标识；发生目录版本切换时，旧会话不得用新定义继续执行旧计划。 |
| SC-FR-13 | 目录变更沿用项目隐私边界：配置与评估记录不包含密钥、Mock 明细、个人信息或模型问题原文；发给模型的目录上下文仍按问题最小化。 |

## 8. 用户流程

1. 维护者在版本控制下编辑目录定义或别名，并更新目录版本/变更记录。
2. 运行目录校验；若结构、引用、别名或执行能力不合规，校验失败并指出条目位置。
3. 校验通过后运行受影响的黄金问题和安全负例；结果与批准预期比较。
4. 评审差异并发布；应用加载新目录快照，查询证据显示该版本。
5. 若发现问题，回退至上一通过版本；重新加载后旧快照会话被要求重开或重述。

## 9. 验收标准

| ID | 关联需求 | 二元验收标准 |
|---|---|---|
| SC-AC-01 | SC-FR-01–02 | 当前电商目录能以一个机器可读配置加载；其 ID、版本、数据集兼容、时区/时间边界策略、三项首版指标、维度、字段关系/聚合约束和已批准术语与 P3 评审文档一致。 |
| SC-AC-02 | SC-FR-05 | 分别注入重复 ID、缺少必填定义、悬空引用和错误数据集 ID；每种情况均被校验拒绝，并给出条目/字段定位。 |
| SC-AC-03 | SC-FR-03、06 | 将一个别名映射到两个指标时校验失败；将术语显式标为歧义时，问数返回澄清/拒答且查询执行数为 0。 |
| SC-AC-04 | SC-FR-04、09 | 配置一个没有后端允许实现 ID 的新指标；它不会出现在可执行目录中，相关提问不触发数据库查询。 |
| SC-AC-05 | SC-FR-07 | 在临时验收目录中为一个已支持指标添加无冲突别名；确定性解析和模型上下文都从该配置读到别名，页面口径说明及 API 证据使用相同定义与目录版本。 |
| SC-AC-06 | SC-FR-08、12 | 加载禁用/不兼容目录或跨版本旧会话时不执行旧计划，并明确要求重开会话或重述问题。 |
| SC-AC-07 | SC-FR-10 | 文案修订、兼容扩展、语义破坏性修改分别校验补丁/次版本/主版本规则；无版本变更的语义编辑不通过目录检查。 |
| SC-AC-08 | SC-FR-11 | 初始目录迁移后，既有 P6 黄金问数的状态、数值、筛选、图表及关键拒答/澄清行为全部与基线一致；P7 已有模型意图黄金集全部通过。 |
| SC-AC-09 | SC-FR-12 | 发布两个有效目录版本后回退到前一版本；应用证据显示前一版本，适用黄金回归恢复原结果。 |
| SC-AC-10 | SC-FR-13 | 检查目录文件、模型请求正文与评估报告；不存在 API Key、订单明细、查询结果或用户原始问题文本。 |
| SC-AC-11 | SC-FR-05、08 | 人为损坏当前活动目录后启动应用；应用不得静默使用内置旧常量，应阻止启用问数并给出不含敏感值的目录错误。 |

## 10. 已确认的实现前提

1. 仓库内配置文件 + Git 评审维护，首版不做网页编辑器。
2. 配置不单独开放新查询能力；新能力仍需改后端和验收。
3. 口径变更/兼容扩展/纯文案修订分别使用主/次/补丁版本。

项目方于 2026-11-10 确认上述三项。SDD 和任务拆分见 [P8-3 SDD](P8_SEMANTIC_CATALOG_SDD.md)。
